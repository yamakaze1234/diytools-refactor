# 三店 NAS 客户端

当前功能分支：`codex/nas-production-three`。三店访问、草稿显式保存、回执恢复、配置归档、价格页和预览内存优化沿用已验收逻辑。数据库自动清理已暂停，单独保存在 `codex/nas-history-retention`，不属于本客户端交付。

## 直接启动

以 `formal-nas-client` 特性和 `src-tauri/tauri.nas-intel-production.conf.json` 构建。配置文件名暂沿用旧名以兼容已有构建脚本，程序名称和窗口标题沿用旧版 DIY Tools；应用 identifier 保持原值以保护已有会话。

便携目录沿用旧版 EXE 文件名，不增加 NAS 后缀。首次没有有效连接时打开连接设置页，填写连接名称、正式局域网 HTTPS 地址，按需导入 PEM 格式 CA；匿名测试通过才可保存并重启，随后使用原有账号登录。登录密码支持显示/隐藏，提交或打开连接设置时清空密码。以后通过“更多 → 连接设置”修改，登录页也提供连接入口。

新设置保存为程序旁 `workbench-connection.json`，包含连接名称、地址、自动核对的部署标识和公开 CA（或标准 HTTPS 信任），单文件原子替换；不含账号、密码或令牌。保存时再次检查服务端，并通过工作台退出前保护确认当前操作已完成，重启后才切换运行时。已有登录和草稿仍按端点与部署标识隔离，原 `data/webview2` 不迁移、不删除。配置错误进入修复界面，不退回本机 SQLite。

正式客户端沿用局域网地址、正式端口和部署代号限制。登录、会话续期及退出通过同一个 NAS HTTPS 地址完成，无需配置外部账号服务。迁移期使用原用户名和密码登记一次，随后沿用已登记的本地凭据。Windows 凭据管理器中的 NAS 续期信息与旧会话分开；草稿继续按原部署、工作区和 UID 找回。

`nas-launch.json` 包含 `version: 1`、`api_url`（正式局域网 HTTPS 根地址）、`deployment_id`（既有正式部署代号）。实际地址和部署文件只保存在交付目录，不进入源码。旧连接的服务端信任证书使用 `data/nas-ca.pem`；没有新连接文件时兼容读取这组旧文件。原 CMD 的环境配置保留兼容，配置文件存在时以配置文件为准；辅助探针保持原参数语义。

## 更新与数据

同一 NAS 版本线在原目录更新 EXE，保留 data、证书、接入配置及旁置连接配置，不在升级时删除登录、草稿或恢复队列。旧本地工作台与 NAS 工作台分目录保留，稳定后另行核对旧数据再清理；本功能不自动迁移或删除旧目录。

## 验证范围

Rust 测试覆盖正式地址/部署校验、拒绝试验端口和 URL 凭据、直启与旧启动器的数据作用域一致。桌面单元/真实页面隔离验证和 Windows 构建证据保存在本轮交付记录。原生双击与员工业务验收须对应实际操作记录，不以构建成功替代。


## 新版更新通道

后续只维护服务端工作台；旧版 refactor-updates 保持冻结。正式特性使用独立的 workbench-updates 标签、workbench-vX.Y.Z 版本标签、diytools-workbench-windows-x86_64.json 签名清单和 diytools-workbench-X.Y.Z-windows-x86_64.exe 附件；沿用既有公钥与 Gitea/GitHub 固定仓库。界面和安装目录中的 EXE 名称不受内部附件名影响。

签名必须匹配 appId io.diytools.nas-intel-production、channel workbench 和 Windows x64 平台。新版不读取旧通道，旧客户端也不能接受新版清单。检查/下载期间可继续编辑；安装先冻结页面并等待草稿落盘及进行中的操作完成，图片导出期间拒绝退出。安装只替换当前 EXE，保留 nas-launch.json、便携标记和 data；新版不打开、备份、回滚旧 SQLite。初始化成功后返回更新回执，启动失败仍可回退 EXE。

本地签名候选使用 tools/prepare-workbench-update.mjs，要求干净源码和实际编译/通道核验报告；只生成 EXE、清单、说明和构建记录，不生成包含用户配置的公开 ZIP，不修改线上通道。旧版发布脚本的默认通道不能用于新版。发布须在用户授权后将同一 EXE 和签名清单放入对应版本 Release，完成两源回读后再推进 workbench-updates。首次安装所需的连接配置和证书仍由既有私有交付提供，不进入公开附件。
