# DIY Tools Windows 工作台使用说明

## 安装与首次使用

从 [Gitea Releases](https://gitea.cq360.top/CoreStudio/diy-tools-refactor/releases) 下载 Windows 便携 ZIP，完整解压至可写目录，运行 `DIYTools.exe`。Windows 需安装 Microsoft Edge WebView2 Runtime。程序首次运行会在旁边建立 `data`，配置、素材、历史和草稿均保存在这里。

没有外部连接配置时直接进入本机工作台，可以编辑、保存和导出。已配置团队服务时，按启动登录界面登录。发行包不附带成员账号或现有团队数据，接入由管理员按[本机可选接入](PUBLIC-INTEGRATIONS.md)准备。

团队内部使用包可由管理员附带本机连接配置。新电脑完整解压后，用自己的成员账号登录即可接收云端现有配置和原图；首次同步完成后再开始编辑。请保留旧程序，确认云端已经包含旧程序中要迁移的资料。此流程不会自动搬运尚未同步的旧本机草稿、历史版本或个人登录状态。已有本机配置的目录不会按“空库”直接接入，以免混合两个来源的数据。

## 配置与图片

1. 选择店铺、商品链接和配置。列表先加载索引，点击配置后读取详情；当前编辑配置保持加载。
2. 修改名称、配件、数量、价格或说明，保存到本机。ERP 成本与库存需要可用的本机适配器，先查看查询差异再应用。
3. 调整配置图或 SKU 图并导出。批量导出按 `链接名称_配置图`、`链接名称_sku图` 创建文件夹，文件名冲突时追加编号，避免覆盖已有文件。
4. 出现保存冲突时保留当前输入，在提示中比较版本，或先备份草稿再重新载入。未确认保存成功前不要强制结束程序。

## 数据与同步

普通编辑先保存在本机；本机保存成功不等于团队同步完成。连接并登录后每 2 小时自动同步，也可在“数据与同步”点击“立即同步”。查看最近同步、待同步和错误状态；有冲突时按提示处理。

同步在后台运行，可以关闭同步窗口继续编辑、查看历史和缓存。还原配置或实际清理缓存需要等当前同步结束。同步期间的新增修改仍应保存本机，并在后续同步中提交。

“数据与同步 → 清理本机缓存”可查看并清理缓存。程序每 3 天自动清理一次，关闭期间到期会在下次启动后补做。过期且无引用的旧生成图会直接删除；每套配置各版式的最新生成图、原图、配置、历史记录和恢复草稿保留。缓存清理不能代替数据备份。

## 一键更新

打开“更多 → 检查更新”，有新版时点击“一键更新”。程序先从 Gitea 匿名读取更新，不需要用户填写 Gitea 令牌。Gitea 不可用时尝试 GitHub 备用源；如果备用仓库为私有，需有其读取权限，才使用更新窗口中的 GitHub 授权设置或本机已登录的 GitHub CLI。

下载后会核验清单签名、版本、程序长度和 SHA-256，保存当前工作台，再退出、替换程序并重启。保存失败会停止安装，输入仍然保留。更新保留 `data` 与本机集成配置，并保留旧程序用于回退。

从 0.2.0 / 0.2.1 升级时，已有客户端仍通过原 GitHub 更新通道读取兼容清单；安装 0.2.2 后改为 Gitea 优先。如果原客户端无法访问 GitHub，可正常退出后从 Gitea 下载新版，将新版 EXE 放回原安装目录，沿用原 EXE 文件名，并保留原 `data` 和 `diytools-portable.json`。

更早的 0.1.0 测试版需要先由管理员把原内置连接、配件目录与可选 ERP 运行时迁移为本机文件，再替换程序。不要用空的新 `data` 覆盖原数据。

## 备份与排错

正常关闭工作台后备份整个程序目录，至少保留完整 `data`。换电脑需要重新处理本机加密凭据；复制数据库不代表已登录或具有外部服务权限。

| 现象 | 处理 |
| --- | --- |
| 保存失败或提示版本变化 | 保留输入，先下载草稿或比较版本，再决定重载 |
| 登录或同步失败 | 检查网络、本机接入配置和成员权限；确认本机保存状态 |
| ERP 功能不可用 | 检查本机适配器与运行时；本地编辑和出图可以继续 |
| 检查更新失败 | 查看更新窗口原因，或从 Gitea Release 手动下载；保留原数据 |
| 图片导出失败 | 保留配置，检查所用素材是否可读，再重试失败项 |

实际连接、账号、登录缓存、私有适配器和业务数据仅留本机，不属于程序发行包。
